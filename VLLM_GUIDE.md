# 🚀 Ускорение генерации паролей с vLLM

## Введение

Этот guide описывает как использовать **vLLM** для ускорения генерации паролей в 3-5 раз. vLLM — это высокооптимизированный движок вывода LLM, который обеспечивает:

- **+3-5x ускорение** благодаря эффективному батчингу
- **80-90% GPU utilization** (вместо 20-10%)
- **KV-cache оптимизация** для beam search
- **Поддержка LoRA адаптеров**

## Как работает

### Проблема с обычным подходом
```python
# Обычный transformers:
for old_password in passwords:
    guesses = model.generate(...)  # Генерирует одну на одну
    # GPU использует только ~20% мощности
```

### Решение с vLLM
```python
# vLLM с батчингом:
client.completions.create(
    prompt=prompts,  # Список промптов!
    # vLLM автоматически:
    # - батчит запросы
    # - оптимизирует KV-cache
    # - распараллеливает генерацию
)
# GPU использует 80-90% мощности
```

## Установка и запуск

### 1️⃣ Подготовка (один раз)

В notebook, в ячейке с конфигурацией:

```python
# Включить vLLM
USE_VLLM = True  # Установите True для использования vLLM

# Параметры (опционально, используются defaults)
VLLM_GPU_MEMORY_FRACTION = 0.85  # 85% GPU памяти
VLLM_MAX_NUM_SEQS = 256  # Макс параллельных sequences
VLLM_BATCH_SIZE = 32  # Размер батча
```

### 2️⃣ Запуск эволюции

Просто запустите ячейки по порядку:

1. ✅ Ячейка с конфигурацией (с `USE_VLLM = True`)
2. ✅ Ячейка "Запуск vLLM сервера" — автоматически запустит vLLM
3. ✅ Остальные ячейки как обычно

Система автоматически:
- Установит vLLM если не установлен
- Запустит vLLM сервер на порту 8000
- Загрузит модель и LoRA адаптер
- Переключит evaluator на vLLM режим

## Параметры оптимизации

### `VLLM_GPU_MEMORY_FRACTION` (0.0 - 1.0)
- **Что это**: Какую часть GPU памяти использовать
- **Значение по умолчанию**: 0.85
- **Рекомендация**: 
  - RTX 4090 / A100: 0.9
  - RTX 3090 / A10: 0.85
  - Меньше памяти: 0.75

### `VLLM_MAX_NUM_SEQS` (int)
- **Что это**: Максимальное количество параллельных sequences
- **Значение по умолчанию**: 256
- **Влияние**:
  - Выше = лучший батчинг, больше памяти
  - Ниже = экономнее, медленнее
- **Рекомендация**: 128-256 для большинства

### `VLLM_BATCH_SIZE` (int)
- **Что это**: Размер батча для обработки запросов
- **Значение по умолчанию**: 32
- **Рекомендация**: 16-64 в зависимости от памяти

### `VLLM_GPU_MEMORY_FRACTION` (bool)
- **Что это**: Использовать eager execution
- **Значение по умолчанию**: False
- **Когда использовать**: True если есть ошибки CUDA

## Отладка проблем

### ❌ "vLLM сервер не запустился вовремя"

**Решение:**
```python
# Проверьте что GPU свободна
!nvidia-smi

# Уменьшите memory fraction
VLLM_GPU_MEMORY_FRACTION = 0.7  # Вместо 0.85

# Или используйте обычный evaluator
USE_VLLM = False
```

### ❌ "CUDA out of memory"

**Решение:**
```python
# Уменьшите batch size
VLLM_BATCH_SIZE = 16  # Вместо 32

# Или уменьшите max sequences
VLLM_MAX_NUM_SEQS = 128  # Вместо 256

# Включите eager execution (медленнее, но стабильнее)
VLLM_ENFORCE_EAGER = True
```

### ❌ "Не удалось подключиться к vLLM"

**Решение:**
```python
# Проверьте что сервер запущен
!curl http://127.0.0.1:8000/v1/models

# Перезапустите notebook и попробуйте снова
# Убедитесь что нет других процессов на порту 8000
!lsof -i :8000
```

## Переключение режимов

### Использовать vLLM (быстро, много памяти)
```python
USE_VLLM = True
VLLM_GPU_MEMORY_FRACTION = 0.85
```

### Использовать обычный evaluator (медленно, экономнее)
```python
USE_VLLM = False
```

### Гибридный режим (автоматический fallback)
```python
USE_VLLM = True
# Если vLLM не запустится, автоматически переключится на обычный
```

## Советы для максимума производительности

1. **Закройте другие приложения** - освободьте GPU память
2. **Используйте правильный `max_num_seqs`** - больше = лучше батчинг
3. **Отключите логи** - логирование замедляет: `VLLM_DISABLE_LOG_STATS = True`
4. **Используйте float16** - vLLM автоматически (быстрее, мало памяти)
5. **Мониторьте память** - `nvidia-smi` в отдельном окне

## Часто задаваемые вопросы

**Q: Зачем нужно GPU 85% вместо 100%?**
A: Оставляем запас для служебной памяти CUDA и spike использования.

**Q: Может ли быть медленнее vLLM чем обычный?**
A: Только если GPU очень мала (<2GB) или много других процессов.

**Q: Как отключить vLLM если не хочу?**
A: `USE_VLLM = False` - вернется к обычному evaluator.

**Q: Поддерживает ли vLLM несколько GPUs?**
A: Да, но текущий код использует одну. Для нескольких:
```python
"--tensor-parallel-size", "2"  # для 2 GPUs
```
